# 放置RPG 初期仕様 v0（ドラフト）

このドキュメントは「最初に何を作るか」を決めるための叩き台です。
各章の末尾に **[要決定]** を置いてあるので、そこだけ潰せば実装に入れます。

---

## 1. コンセプト

> **FINAL FANTASY XI をオマージュした、ジョブ制の放置RPG。**
> 4人パーティが自動で連戦し続ける。
> プレイヤーがやることは **「編成するジョブの組み合わせ」** と
> **「アビリティを今使うか、温存するか」** の2つだけ。

- 通常攻撃・ターゲット選択・ウェポンスキルはすべて自動
- 戦闘中の入力は **アビリティボタンを押す／押さない** のみ
- ステージは **10連戦**。HP・MP・リキャストは**戦闘をまたいで持ち越す**
  → 「1戦目でケアルガを撃つか、ボスまで残すか」が意思決定になる

**このゲームの核心**

戦闘中は「リソースをどこで吐き出すか」の判断だけ。
戦闘外は「どのジョブを並べるか」の判断だけ。
この2つ以外の操作は全部消す。

**やらないこと（v0では）**
- サポートジョブ（v1で実装）
- マルチプレイ、ランキング、課金
- 手動でのターゲット指定・隊列変更
- ストーリーテキストの作り込み

### 1.1 オマージュの扱い

ジョブ名・アビリティ名・ステータス表記（STR/DEX/VIT/AGI/INT/MND/CHR）・
「ジョブ特性」「リキャスト」「TP」「ウェポンスキル」などの用語は FF11 のものを踏襲する。
数値やレベル習得タイミングは、本作のバランスに合わせて調整する（原作準拠ではない）。

なお、これらの固有名詞は権利者のものなので、**一般公開・配布する段になったら**
名称を独自のものへ差し替えるか、非商用の個人制作として扱うかを決める必要がある。
開発中は FF11 の名称のまま進めて問題ない（後から名前だけ差し替えられるよう、
**ジョブ・アビリティの定義はすべてデータテーブルに切り出す**）。

## 2. 技術構成

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 実行環境 | ブラウザ単体（HTML + CSS + 素のJS、ビルド不要） | `index.html` を開くだけで動く。GitHub Pages にそのまま公開できる |
| 言語 | JavaScript (ES2022, ESModules) | ビルドツール無しでモジュール分割できる |
| セーブ | `localStorage` に JSON 1件 | サーバ不要 |
| 描画 | DOM + CSS（Canvas は使わない） | HPバーとボタンが主体なので DOM の方が速い |
| データ定義 | `data/jobs.js` `data/abilities.js` `data/equipment.js` に分離 | ジョブ追加（22ジョブ化）と名称差し替えをコード変更なしで行うため |
| 対応 | PC / スマホ縦持ち（レスポンシブ） | アビリティボタンは親指が届く下部に置く |

**[要決定]** TypeScript + Vite に切り替えるか。
→ ジョブ・アビリティ・装備のデータ量が増えるので、前案より型の価値は高い。
　それでも推奨は「v0は素のJSで作り切る」。動くものが出るまでを最短にしたい。

## 3. ジョブ

### 3.1 全体像

FF11 の 22ジョブを最終的に実装対象とする。v0 では **初期6ジョブ**のみ作る。

| 区分 | ジョブ | 実装 |
| --- | --- | --- |
| 初期ジョブ（6） | 戦士 / モンク / 白魔道士 / 黒魔道士 / 赤魔道士 / シーフ | **v0** |
| 上級ジョブ（16） | ナイト / 暗黒騎士 / 獣使い / 吟遊詩人 / 狩人 / 侍 / 忍者 / 竜騎士 / 召喚士 / 青魔道士 / コルセア / からくり士 / 踊り子 / 学者 / 風水士 / 魔導剣士 | v2以降、順次 |

上級ジョブは「特定条件で解放」する（FF11のジョブクエスト相当）。
条件の設計は v2 で行うが、**データ構造には最初から `unlockCondition` を持たせておく**。

### 3.2 ジョブが持つもの

ジョブごとの違いは、以下の5つで表現する。

| 要素 | 内容 |
| --- | --- |
| **ステータス補正** | 7ステータス＋HP/MPの成長率を A+〜F のグレードで定義 |
| **固有アビリティ** | ジョブレベルで習得。リキャストを持つ能動的な技・魔法 |
| **ジョブ特性（パッシブ）** | ジョブレベルで習得。常時発動 |
| **ジョブレベル** | ジョブごとに独立して蓄積（キャラ単位ではない） |
| **装備** | 装備可能な武器種・防具ランクがジョブごとに異なる |

### 3.3 ステータス

FF11 に倣い、以下を持つ。

`HP / MP / STR / DEX / VIT / AGI / INT / MND / CHR`

成長率はグレードで定義する。

| グレード | 係数 |
| --- | --- |
| A+ | 1.00 |
| A | 0.90 |
| B | 0.80 |
| C | 0.70 |
| D | 0.60 |
| E | 0.50 |
| F | 0.40 |

```
STR等 = floor( 5 + 係数 × (Lv - 1) × 1.1 )
HP    = floor( 30 + HP係数 × (Lv - 1) × 12 )
MP    = floor( MP係数 × (Lv - 1) × 7 )      // F は MP 0
```

### 3.4 ジョブレベル

- **ジョブごとに独立**して EXP が蓄積される（FF11 と同じ）
- EXP は **編成に入れているジョブにのみ**入る
  → 「今のステージを進めたい」か「別ジョブを育てたい」かのトレードオフになる
- レベル上限は **75**（FF11 初期の上限へのオマージュ）

```
次レベルまでの必要EXP = floor( 20 × Lv^1.7 )
敵1体の獲得EXP        = floor( 4 × 1.30^(ステージ-1) )
```

レベル上限があるので、ここは**有限の育成**。
無限に伸びるスケーリングは「装備」と「転生」が担当する（後述）。

**[要決定]** レベル上限 75 でよいか（FF11 は後に 99 まで解放された）。
→ 推奨は 75。上限解放そのものを、後々のアップデート要素として使える。

## 4. パーティ編成

- パーティは **4枠**。解放済みジョブから自由に組む
- **同一ジョブの重複は不可**（v0）
- 編成の変更は戦闘外ならいつでも可能。ペナルティなし
- 編成に入っているジョブにのみ EXP が入る

編成が意味を持つように、役割は明確に分ける。

| 役割 | 該当ジョブ | 抜けると起きること |
| --- | --- | --- |
| 盾 | 戦士 / モンク | 後衛が直接殴られて溶ける |
| 回復 | 白魔道士 / 赤魔道士 | 連戦の後半で立て直せない |
| 単体火力 | シーフ / 戦士 | ボスが時間内に落ちない |
| 全体火力 | 黒魔道士 | 雑魚戦が長引き、その間に削られる |
| 経済 | シーフ | 装備の更新が遅れる |

6ジョブから4枠なので、**必ず何かを捨てる**構成になる。ここが編成の面白さになる。

**[要決定]** パーティ人数を 4人 と 6人 のどちらにするか。
→ FF11 のパーティは 6人 なので、オマージュとしては 6人 が忠実。
　ただし 6人 にすると 22ジョブでも「ほぼ全役割を積める」状態になり、編成の悩みが減る。
　推奨は **4人のまま**（捨てる判断を残したい）。忠実さを取るなら 6人。

**[要決定]** 同一ジョブの重複を許すか。
→ FF11 では可能。ただし許すと「白×2」「黒×4」のような極端な最適解が出やすい。
　推奨は v0では不可。

## 5. 戦闘

### 5.1 進行

```
ステージ開始（HP/MP/リキャストは全快・全リセット）
      ↓
 1戦目：敵1〜3体が出現
      ↓  全滅させると即座に次の戦闘へ
 2戦目 … 9戦目          ← HP・MP・リキャストは持ち越し
      ↓
 10戦目：ボス（NM扱い・単体）
      ↓
 勝利 → 次のステージへ ／ 全滅 → 同じステージの1戦目から
```

- **戦闘間の自動回復は HP 5% のみ**（＝連戦するほど削られていく）
- 全滅のペナルティは無し（失うのは時間だけ）。獲得済みのゴールドとEXPは保持

### 5.2 リアルタイム処理

100ms ティックで進行する。ターン制ではない。

- 各キャラと各敵は「行動ゲージ」を持ち、`行動速度 × 経過秒` で溜まる
- ゲージ満タン → 通常攻撃 → ゲージ0
- ターゲットは自動（味方は敵HPが最も低い個体、敵はランダム。プロヴォーク中は該当者に固定）

```
攻撃力     = 武器D + STR × 0.5
物理ダメージ = 攻撃力 × 100 / (100 + 敵DEF) × (0.9〜1.1)
魔法ダメージ = 魔法基本値 × 100 / (100 + 敵MDEF)
命中率      = 75 + (DEX - 敵AGI) × 0.5   （上限95% / 下限20%）
```

### 5.3 TP とウェポンスキル

FF11 の TP システムを踏襲する。

- 通常攻撃を当てるたびに TP が +8%（最大100%）
- **TP 100% で自動的にウェポンスキルが発動**する（プレイヤー操作なし）
- ウェポンスキルは武器種ごとに固定（例：短剣＝ダンシングエッジ、格闘＝連発掌）

**[要決定]** ウェポンスキルを手動発動にするか。
→ 手動にすると判断が増えるが、ボタンが 4つ増えて画面がうるさくなる。
　推奨は v0は自動。「連携（スキルチェーン）」を入れるなら v2 で手動化を再検討。

### 5.4 アビリティ操作

画面下部にボタンを並べる。押せる時だけ光る。

- **アビリティ枠は 1キャラにつき 2つ**。習得済みのアビ・魔法から自由にセットできる
- 合計 **8ボタン**（4人 × 2枠）
- 1時間アビもこの2枠のうち1つを使う
  → 「1時間アビを積むか、回転の速いアビを2つ積むか」も編成の判断になる
- **MPはキャラ個別**（FF11 準拠。戦士・モンクは MP 0）
- **リキャストは戦闘をまたいで継続する**（戦闘終了でリセットされない）

MPもリキャストも「今使うと、ボス戦で使えない」という形で効いてくる。
これが本作の唯一のジレンマなので、ここだけは絶対に単純化しない。

### 5.5 オート（放置）モード

トグルONで、AIがアビリティを自動使用する。

| | 手動 | オート |
| --- | --- | --- |
| アビの使い方 | プレイヤー判断 | 撃てるようになったら即撃つ |
| 結果 | 効率が良い（ボス前に温存できる） | 効率が落ちる（ボス戦でリキャスト中になりがち） |

**手動プレイの方が明確に強い**設計にする。
そのうえでオートでも「じわじわ進む」ようにして、放置ゲームとして成立させる。

**[要決定]** オートAIを賢くするか（HP50%以下でケアル、ボス戦のみ1時間アビ、など）。
→ 推奨は「v0は素直な即撃ちAI」。賢いAIは**転生報酬として後から売る**方が筋が良い。

## 6. 装備

ジョブレベルが上限 75 で止まるので、**無限に伸びる軸は装備が担う**。

### 6.1 スロット

v0 は 3スロット。

| スロット | 例 |
| --- | --- |
| 武器 | ブロンズソード / ブロンズナイフ / 樫の杖 |
| 胴 | ブロンズハーネス / ローブ |
| 装飾 | 各種リング・イヤリング |

FF11 の 16スロットは v2 以降に拡張する（データ構造は `slot` 文字列で持たせる）。

### 6.2 装備条件

FF11 の表記を踏襲する。

```
ブロンズソード      Lv1  戦赤ナ暗
バトルアックス      Lv10 戦
ヒーラーズローブ    Lv20 白赤
```

- **ジョブ制限**と**レベル制限**の両方を持つ
- ジョブを変えると装備できなくなる → 「別ジョブを育てるなら装備も要る」というコスト

### 6.3 入手と強化

- **店で購入**（ゴールド）。品揃えは **10ステージごとに新ティアが解放**される
- ステージが無限に続く以上、装備ティアも無限に続く ＝ 無限スケーリングの受け皿
- 装備は **+0 〜 +10** に強化できる（1段階ごとに性能 +8%）

```
装備ティア t の武器D  = floor( 6 × 1.42^(t-1) )
店売り価格            = floor( 300 × 1.45^(t-1) )
強化コスト(+n → +n+1) = floor( 価格 × 0.5 × 1.5^n )
```

**[要決定]** 装備をドロップ入手にするか、店売りのみにするか。
→ 推奨は v0は店売りのみ。ドロップを入れるとインベントリ管理のUIが必要になり、
　「操作を減らす」というコンセプトと衝突する。

## 7. 経済（何が何で伸びるか）

| 通貨 | 入手 | 使い道 | 性質 |
| --- | --- | --- | --- |
| **EXP** | 敵撃破（編成中のジョブのみ） | ジョブレベル | 有限（上限75） |
| **ゴールド** | 敵撃破 | 装備の購入・強化 | 無限 |
| **魂（Soul）** | 転生 | 全体倍率 | 無限（v1） |

この3層構造にしておくと、

- 短期（数分）：ゴールドが貯まり、装備が1段強くなる
- 中期（数時間〜数日）：ジョブが育ち、新しいアビリティと特性が開く
- 長期（数週間）：転生倍率で全体が底上げされ、別ジョブを育て直せる

という、放置ゲームに必要な3つの時間スケールが揃う。

### 7.1 敵の数値

| 項目 | 式 | ステージ1 | ステージ10 | ステージ30 |
| --- | --- | --- | --- | --- |
| 通常敵HP | `40 × 1.45^(n-1)` | 40 | 約 1.5k | 約 6.6e5 |
| 通常敵ATK | `5 × 1.42^(n-1)` | 5 | 約 150 | 約 5.0e4 |
| 敵DEF | `2 × 1.40^(n-1)` | 2 | 約 58 | 約 1.5e4 |
| ボスHP | 通常敵HP × 15 | 600 | 約 22k | 約 9.9e6 |
| ゴールド | `8 × 1.40^(n-1)` | 8 | 約 232 | 約 1.3e5 |
| EXP | `4 × 1.30^(n-1)` | 4 | 約 42 | 約 7.4k |

- 敵HPの伸び（1.45）> ゴールドの伸び（1.40）＝ 進むほど自然に詰まる
- EXPの伸び（1.30）は最も緩い ＝ レベルは先に頭打ちになり、装備での更新が主役になる

### 7.2 転生（プレステージ）— v1で実装

- 解放条件：ステージ25のボス撃破
- リセット対象：ステージ、ゴールド、装備、**ジョブレベル**
- 獲得：**魂（Soul）**

```
獲得魂     = floor( (最高到達ステージ / 25) ^ 1.6 )
転生倍率   = 1 + 総魂数 × 0.10        // 全ダメージ・最大HP・獲得EXPに乗算
```

ジョブレベルをリセット対象に含めるのは、獲得EXP倍率が乗ることで
**2周目以降のジョブ育成が速くなる＝別ジョブを試しやすくなる**ため。

**[要決定]** 転生でジョブレベルをリセットするか、維持するか。
→ 維持だと「転生してもパーティが変わらない」ので周回の景色が変わらない。
　推奨はリセット。ただし**解放済みジョブの一覧は維持**する。

## 10. オフライン報酬

- ゲームを閉じた時刻を保存し、次回起動時に経過秒を計算する
- **最高到達ステージの1つ前**を、オートモードで周回したものとして報酬を計算する
  （オフライン中にステージは進まない ＝ 放置で壁は超えられない）

```
オフライン獲得 = (ステージ報酬 / ステージ攻略秒) × 経過秒 × 0.5
```

- ゴールドと EXP の両方が入る（EXPは編成中のジョブのみ）
- **効率50%**、**上限12時間**
- 起動時に「留守中の成果」モーダルを出す

**[要決定]** 効率と上限（50% / 12時間）。「80% / 24時間」でも成立する。
