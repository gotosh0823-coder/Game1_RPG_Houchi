# 放置RPG 初期仕様 v0（ドラフト）

このドキュメントは「最初に何を作るか」を決めるための叩き台です。
各章の末尾に **[要決定]** を置いてあるので、そこだけ潰せば実装に入れます。

---

## 1. コンセプト

> 4人パーティが自動で戦い続ける。
> プレイヤーがやることは **「アビリティを今使うか、温存するか」** の判断だけ。

- 通常攻撃・ターゲット選択・移動はすべて自動
- プレイヤーの入力は **アビリティボタンを押す／押さない** のみ
- ステージは **10連戦**。HPとアビリティのクールタイムは**戦闘をまたいで持ち越す**
  → だから「1戦目で回復を使うか、ボスまで残すか」が意思決定になる

**このゲームの核心**

放置ゲームだが、**リソース（HP・MP・CT）を連戦のどこで吐き出すか**という
1つの判断だけを、プレイヤーに繰り返し問うゲームにする。
それ以外の操作は全部消す。

**やらないこと（v0では）**
- パーティ編成の入れ替え（4人固定）
- マルチプレイ、ランキング、課金
- 手動でのターゲット指定・隊列変更
- ストーリーテキストの作り込み

## 2. 技術構成

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 実行環境 | ブラウザ単体（HTML + CSS + 素のJS、ビルド不要） | `index.html` を開くだけで動く。GitHub Pages にそのまま公開できる |
| 言語 | JavaScript (ES2022, ESModules) | ビルドツール無しでモジュール分割できる |
| セーブ | `localStorage` に JSON 1件 | サーバ不要 |
| 描画 | DOM + CSS（Canvas は使わない） | HPバーとボタンが主体なので DOM の方が速い |
| 対応 | PC / スマホ縦持ち（レスポンシブ） | アビリティボタンは親指が届く下部に置く |

**[要決定]** TypeScript + Vite に切り替えるか。
→ 推奨は「v0は素のJSで作り切る」。ただし戦闘シミュレータの状態管理が増えるので、
　v1で型が欲しくなる可能性は前回より高い。

## 3. パーティ

4人固定。役割が被らないように最小構成で組む。

| # | 職業 | 役割 | HP | ATK | SPD | アビリティ |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 戦士 | 壁・敵の攻撃を引き受ける | 200 | 10 | 1.0 | **挑発** |
| 2 | 盗賊 | 単体高火力 | 120 | 18 | 1.4 | **乱れ撃ち** |
| 3 | 僧侶 | 回復 | 130 | 7 | 0.9 | **全体回復** |
| 4 | 魔法使い | 全体火力 | 100 | 14 | 0.8 | **メテオ** |

- 数値は Lv1 時点の初期値（後述の強化で伸びる）
- SPD = 1秒あたりの行動回数。1.4 なら約0.71秒に1回、通常攻撃する
- 戦闘不能になったメンバーは、そのステージが終わる（or 全滅する）まで復帰しない

**[要決定]** 4人を固定にするか、後から仲間を増やして入れ替え可能にするか。
→ 推奨は「v0は4人固定」。編成を入れられると、プレイヤーの判断が
　「アビを使うか」から「誰を入れるか」に移ってしまい、コンセプトがぶれる。

## 4. 戦闘

### 4.1 進行

```
ステージ開始（HP/MP/CTは前のステージから引き継がない＝ステージ頭は全快）
      ↓
 1戦目：敵1〜3体が出現
      ↓  全滅させると即座に次の戦闘へ（間に休憩なし）
 2戦目 … 9戦目          ← HP・MP・CTは持ち越し
      ↓
 10戦目：ボス
      ↓
 勝利 → 次のステージへ ／ 全滅 → 同じステージの1戦目から
```

- **戦闘間の自動回復は HP 5% のみ**（＝連戦するほど削られていく）
- 全滅してもペナルティは無し（失うのは時間だけ）。獲得済みゴールドは保持

### 4.2 リアルタイム処理

100ms ティックで進行する。ターン制ではない。

- 各キャラと各敵は「行動ゲージ」を持ち、`SPD × 経過秒` で溜まる
- ゲージが満タン → 通常攻撃 → ゲージ0に戻る
- ターゲットは自動選択（味方は敵HPが最も低い個体、敵はランダム。挑発中は戦士に固定）

```
与ダメージ = ATK × 100 / (100 + 相手DEF) × (0.9〜1.1 のランダム)
```

### 4.3 アビリティ（プレイヤーの唯一の操作）

画面下部に4つのボタン。押せる時だけ光る。

| アビリティ | 効果 | MP | CT |
| --- | --- | --- | --- |
| 挑発（戦士） | 8秒間、敵の攻撃対象を戦士に固定＋戦士のDEF2倍 | 20 | 25秒 |
| 乱れ撃ち（盗賊） | 単体に ATK×4 のダメージ | 30 | 20秒 |
| 全体回復（僧侶） | 味方全員のHPを最大値の35%回復 | 40 | 30秒 |
| メテオ（魔法使い） | 敵全体に ATK×2.5 のダメージ | 45 | 35秒 |

- **MPはパーティ共有**。最大100、毎秒3回復
- **CTは戦闘をまたいで継続する**（戦闘終了でリセットされない）
- MPもCTも「今使うと、次の戦闘やボス戦で使えない」という形で効いてくる

これが本作の唯一のジレンマなので、ここだけは絶対に単純化しない。

### 4.4 オート（放置）モード

トグルON で、AIがアビリティを自動使用する。

| | 手動 | オート |
| --- | --- | --- |
| アビの使い方 | プレイヤー判断 | 撃てるようになったら即撃つ |
| 結果 | 効率が良い（ボス前に温存できる） | 効率が落ちる（ボス戦でCT中になりがち） |

**手動プレイの方が明確に強い**設計にする。
そのうえでオートでも「じわじわ進む」ようにして、放置ゲームとして成立させる。

**[要決定]** オートAIをもう少し賢くするか（HP50%以下で回復、ボス戦のみ火力アビ、など）。
→ 推奨は「v0は素直な即撃ちAI」。賢くしすぎると手動でやる理由が消える。
　賢いAIは「オート強化」として転生報酬などで**後から買わせる**のが筋が良い。

## 5. 数値設計

すべて指数関数。定数は後で調整する前提の初期値。

### 5.1 敵

| 項目 | 式 | ステージ1 | ステージ10 | ステージ30 |
| --- | --- | --- | --- | --- |
| 通常敵HP | `40 × 1.45^(n-1)` | 40 | 約 1.5k | 約 6.6e5 |
| 通常敵ATK | `5 × 1.42^(n-1)` | 5 | 約 150 | 約 5.0e4 |
| 敵DEF | `2 × 1.40^(n-1)` | 2 | 約 58 | 約 1.5e4 |
| ボスHP | 通常敵HP × 15 | 600 | 約 22k | 約 9.9e6 |
| ゴールド | `8 × 1.40^(n-1)` | 8 | 約 232 | 約 1.3e5 |

- 敵HPの伸び（1.45）> ゴールドの伸び（1.40）にしてある
  → 進むほど自然に詰まるので、壁を手で置かなくても壁ができる
- ATKの伸びも入っているので、詰まり方が「削り切れない」だけでなく
  「連戦の途中で溶ける」という形にもなる。**回復アビの価値が段階的に上がる**

### 5.2 強化（ゴールド消費）

キャラ個別の強化と、パーティ全体の強化を分ける。

**キャラ強化（4人ぶん個別）**

| 強化 | 効果 | 初期コスト | コスト倍率 |
| --- | --- | --- | --- |
| レベル | HP +8% / ATK +8%（乗算） | 20 | ×1.14 |
| アビリティ強化 | アビ威力 +10%（乗算） | 300 | ×1.30 |

**パーティ強化（共通）**

| 強化 | 効果 | 初期コスト | コスト倍率 |
| --- | --- | --- | --- |
| 最大MP | +10（毎秒回復も+0.2） | 500 | ×1.35 |
| ゴールド獲得 | +5%（乗算） | 250 | ×1.22 |

- 「誰を伸ばすか」も薄い選択になるが、コストが同じなので**最適解は全員均等**にしておく
  （悩ませたいのはアビの使用判断であって、育成の最適化ではない）

**[要決定]** キャラごとに強化を分ける必要があるか。
→ 「パーティ全体で1本のレベル」に統合する案もある。UIは半分になる。
　推奨は個別のまま（画面に4人並ぶので、個別に伸びる方が手応えが出る）。

### 5.3 転生（プレステージ）— v1で実装

- 解放条件：ステージ25のボス撃破
- リセット対象：ステージ、ゴールド、全強化
- 獲得：**魂（Soul）**

```
獲得魂 = floor( (最高到達ステージ / 25) ^ 1.6 )
転生倍率 = 1 + 総魂数 × 0.10        // 全ダメージ・最大HPに乗算
```

## 6. オフライン報酬

- ゲームを閉じた時刻を保存し、次回起動時に経過秒を計算する
- **最高到達ステージの1つ前**を、オートモードで周回したものとして報酬を計算する
  （オフライン中にステージは進まない ＝ 放置で壁は超えられない）

```
オフライン獲得ゴールド = (ステージ報酬 / ステージ攻略秒) × 経過秒 × 0.5
```

- **効率50%**、**上限12時間**
- 起動時に「留守中に◯◯ゴールド稼ぎました」のモーダルを出す

**[要決定]** 効率と上限（50% / 12時間）。「80% / 24時間」でも成立する。

│      👹 ███░░░░░░░                  │
├──────────────────────────┤
│  戦士   ████████░░  盗賊  ██████░░░░ │

├──────────────────────────┤
│  MP ███████░░░ 72/100               │

→ 推奨は「v0は絵文字1文字」（🗡🏹✨🔮 / 🦇🐺👹）。素材集めで止まらないのが最優先。

## 8. データモデル（セーブ）

```js
{
  version: 1,
  stage: 12,
  maxStage: 14,
  battleIndex: 4,          // ステージ内の何戦目か
  gold: 12400,
  souls: 0,                // v1から使用
  autoMode: true,
  members: [               // 4人固定・配列順は職業固定
    { id: "warrior", level: 24, abilityLevel: 3 },
    { id: "thief",   level: 22, abilityLevel: 2 },
    { id: "priest",  level: 23, abilityLevel: 4 },
    { id: "mage",    level: 21, abilityLevel: 2 }
  ],
  party: { mpLevel: 5, goldLevel: 7 },
  lastSeen: 1753459200000,
  settings: { sound: false }
}
```

- **戦闘中のHP/MP/CTはセーブしない**（リロード時はステージの1戦目から再開）
  → 途中状態まで保存すると、リロードでCTを回復させる裏技が成立してしまう
- 保存タイミング：10秒ごと ＋ `visibilitychange` ＋ `beforeunload`
- `version` を見てマイグレーションする
