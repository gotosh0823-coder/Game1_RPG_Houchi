# バランス定数の一覧

実装に入っている倍率・固定値をすべて並べたもの。**コードが正**で、この文書は写し。
値を変えたら、この表も一緒に更新すること。

`⚠` は、変えると壁の位置が大きく動くもの。

---

## 1. 味方が強くなる要素

プレイヤーの戦力に効く数値。これが「強化」の全体像。

### 1.1 ジョブレベル（EXPで伸びる・上限75）

`js/core/stats.js`

| 項目 | 値 | 備考 |
| --- | --- | --- |
| レベル上限 | **75** | `jobs.js` の `LEVEL_CAP` |
| HP 基礎値 | **150** | Lv1の値 |
| MP 基礎値 | **40** | MPグレードFの戦士・モンクは常に0 |
| ステータス基礎値 | **5** | STR/DEX/VIT/AGI/INT/MND/CHR 共通 |
| HP 1レベルあたり | **6** × グレード係数 | |
| MP 1レベルあたり | **3.5** × グレード係数 | |
| ステータス 1レベルあたり | **0.55** × グレード係数 | |
| 必要EXP | ⚠ `floor(9 × Lv^1.9)` | Lv1→2で9、Lv74→75で約3.8万。Lv75までの総量 **約83万** |

```
HP     = floor( (150 + HP係数 × 6 × (Lv-1))   × 限界突破ボーナス ) + 5 × 突破回数
MP     = floor( (40 + MP係数 × 3.5 × (Lv-1))  × 限界突破ボーナス ) + 5 × 突破回数
その他 = floor( (5 + 係数 × 0.55 × (Lv-1))    × 限界突破ボーナス ) + 1 × 突破回数
```

**グレード係数**（`jobs.js` の `GRADE`）

| A+ | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- |
| **2.00** | 1.80 | 1.60 | 1.40 | 1.20 | 1.00 | 0.80 |

> 係数を2倍にしたので、1レベルあたりの伸び（6 / 3.5 / 0.55）と掛け合わせると
> 半減する前の曲線に戻る。Lv50の素のステータスは HP 679（戦士）／
> 主要ステータス 53〜59 程度。

### 1.2 装備（4部位・所持品制）

`js/core/inventory.js` / `js/data/equipment-list.js`。
到達ステージから自動でティアが決まる暫定仕様は**廃止**した。
いまは1本ずつ拾って持ち、ギルでレベルを上げ、同じ名称を重ねて合成する。

| 項目 | 値 | 備考 |
| --- | --- | --- |
| 部位 | 武器 / 鎧 / 脚 / アクセサリ | |
| 所持上限 | **200本** | 超えたぶんは自動でギルに変わる |
| 帯（ドロップ装備の切り替わり） | **50ステージごと** | 全40帯（ステージ1〜2000） |
| 帯倍率 | **1.0**（帯が変わっても基礎値は同じ） | 差は実績ボーナスとガチャ装備で埋める |
| 装備の総数 | **533種**（ドロップ520 / ガチャ13） | `data/equipment.csv` が原本 |

**レア度**（`RARITY`）

| レア度 | 倍率 | レベル上限 | 強化費用の係数 | 合成に必要な数 |
| --- | --- | --- | --- | --- |
| N | 1.0000 | 10 | 1.0 | 2 |
| R | 1.5000 | 20 | 1.5 | 3 |
| SR | 2.2500 | 30 | 2.2 | 3 |
| SSR | 3.3750 | 40 | 3.2 | 3 |
| UR | 5.0625 | 50 | 4.6 | — |

```
実効ステータス = 基礎値 × レア度倍率 × (1 + 0.05 × (レベル - 1))
```

N Lv1 が 1.00 倍、UR Lv50 が 5.0625 × 3.45 = **約17.5倍**。
これがゲーム全体を通しての、装備による伸びの上限になる。
UR1本を作るのに N が 54本 必要（2×3×3×3）。

**強化・合成の費用**（ギル・線形）

```
基準額     = max(40, その帯の開始ステージのゴールド × 2)
レベル+1   = 基準額 × レア度係数 × 現在レベル
合成       = 基準額 × レア度係数 × (上限Lv × (上限Lv+1) / 2) × 0.5
```

帯の開始ステージを基準にしているので、帯の前半は重く、後半は軽い（意図どおり）。

### 1.3 限界突破

`js/core/save.js`。突破回数を N とする。

| 項目 | 値 |
| --- | --- |
| 条件：ジョブレベル | **75** |
| 条件：ゴールド | `到達ステージの1戦闘ゴールド × 10 × 15 × 2^(N-1)` |
| 条件：アイテム | 「偉大な〇〇の証」 **N個** |
| 効果：レベル | **1に戻る** |
| 効果：成長ボーナス | **1 + 0.05 × N**（全ステータスに乗算） |
| 効果：初期ステータス | HP **+5N** / MP **+5N** / その他 **+1N** |
| 効果：獲得EXP | **1 + 0.5 × N** 倍 |

> 固定額（100万ギル）だったが、ギルの伸びを敵に合わせて落とした時点で
> 「一生払えない額」になったため、到達ステージの稼ぎを基準にした
> 相対額に変えた。1回目は約10ステージぶんの稼ぎで貯まる。
> 実際の関門は最後まで「証」（1ボス8%）のほうで、n個集めるのに約12.5nステージ。
> UIは編成画面にある。

## 3. 戦闘の固定値

`js/core/battle.js`

| 項目 | 値 |
| --- | --- |
| ティック | **0.1秒** |
| MP自然回復（全員共通） | **1.0 / 秒** |
| 白の自動ケアル閾値 | HP **70%** 未満 |
| ケアルのMP消費 | **10** |
| ファイアのMP消費 | **8** |
| TP蓄積（命中1回） | **8%** |
| ウェポンスキル倍率 | **×3.0** |
| 戦闘間の自動回復 | 最大HPの **5%** |
| ヘイトの最低保証 | **5%** |

**計算式**

```
ステータス   = レベルぶん + 装備4部位の合計

攻撃力       = 武器のatk + STR × 0.5
魔力         = INT × 1.8
回復量       = MND × 2.5

物理ダメージ = 攻撃力 × 100 / (100 + 敵DEF) × (0.9〜1.1)
魔法ダメージ = 魔力   × 100 / (100 + 敵MDEF)
被ダメージ   = 敵ATK × 敵ATK / (敵ATK + VIT × 2) × (0.9〜1.1)
命中率       = 75 + (DEX - 相手AGI) × 0.5   （20〜95%）
```

**ヘイト**

```
ヘイト = ( 与ダメージ累計
         + 回復量累計 × 0.5
         + デバフ1回ごとに 敵HP × 0.02
         + 女神の祝福1回ごとに 自分の最大HP × 0.5
         + VIT × 10 )                 ← 戦闘開始時の初期値
       × ジョブのヘイト倍率
```

比率をそのまま狙われる確率にし、5%を下回る者は5%へ引き上げ、
不足ぶんを上回っている者から比例して差し引く。

## 4. 敵の数値（強化の対抗軸）

`js/data/enemies.js`。n = ステージ番号。

### 4.1 ⚠ すべて「べき乗」。指数はゲーム内に1つも無い

以前は敵もギルもEXPも指数（`1.09^n` / `1.16^n` など）だった。やめた理由：

- **数字が桁で暴走する。** ステージ100の獲得EXPが「Lv1→75に必要な総量の6倍」
  という状態になっていた（EXPだけ指数を下げ忘れていたことに気づけなかった）
- **調整が効かない。** 指数を 0.01 動かすと壁が10ステージ以上ずれる
- **上限のある強化と噛み合わない。** プレイヤー側の強化はレベル75・
  装備UR Lv50・遺物40個と、どれも上限がある。指数の相手にはいずれ必ず負ける

いまは全部これ。ステージ1で1になり、進むほど**相対的な**伸びが落ちる。

```
倍率 = ((n + 15) / 16) ^ 指数
```

素の `n^p` は序盤が急すぎる（ステージ10で22倍）ため、原点を15ずらしてある。

| 項目 | 式 | 1 | 10 | 25 | 50 | 100 | 150 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1戦闘の総HP | ⚠ `110 × 倍率(3.0)` | 110 | 420 | 1.7k | 7.4k | 41k | 121k |
| 敵ATK | ⚠ `5 × 倍率(3.3)` | 5 | 22 | 103 | 510 | 3.4k | 11k |
| ギル | `8 × 倍率(3.0)` | 8 | 31 | 125 | 536 | 3.0k | 8.8k |
| EXP | `9 × 倍率(3.0)` | 9 | 34 | 141 | 603 | 3.3k | 9.9k |
| 敵DEF | `2 + n × 3` | 5 | 32 | 77 | 152 | 302 | 452 |
| 敵AGI | `2 + n × 1.2` | 3 | 14 | 32 | 62 | 122 | 182 |

ステージ100でも5桁で収まる。

- 通常敵1体のHP = 総HP ÷ 敵数（何体出ても総量は一定）
- DEFとAGIは割合として効くので、**指数で伸ばしてはいけない**（線形にしてある）

### 4.2 指数の選び方（実測）

**総HPの指数 = 到達ステージ**（6回ずつ・詰まったら遺物を取る方針）

| 指数 | 到達 | 備考 |
| --- | --- | --- |
| 2.2 | 147〜149 | 緩すぎる（15時間かかる） |
| 2.6 | 86〜95 | |
| **3.0**（現在） | **93〜105** | |
| 3.4 | 33〜71 | 不安定 |

**敵ATKの指数 = 全滅の回数。** 総HPより速くしないと、詰まり方が
「時間がかかるだけで誰も死なない」になり全滅がほとんど起きない。
遺物は全滅でしか手に入らないので、それでは遺物が開かない。

| ATK指数 | 全滅回数 | 到達 |
| --- | --- | --- |
| **3.3**（現在） | 1〜7回 | 93〜105 |
| 3.5 | 3〜16回 | 74〜79 |
| 3.7 | 14〜28回 | 62〜97（不安定） |
| 3.9 | 24〜86回 | 79〜192（不安定） |

**全滅を増やすと、その回数ぶんきっちり到達ステージが落ちる。**
全滅はステージのやり直しであり、遺物を取ればレベルも15下がるため。
「何度か全滅しながら100に到達」を満たす点として 3.3 を採った。

ボスの全体攻撃（×1.5）を強くする方向でも全滅は増やせるが、
こちらは 1.5 → 2.5 で到達が15ステージ落ちるなど、より割が悪かった。

**ボス（10戦目）**

| 項目 | 値 |
| --- | --- |
| HP | 総HP **×15** |
| ATK | 通常敵の **×1.2** |
| 全体攻撃の間隔 | **20秒ごと** |
| 全体攻撃の倍率 | ATK **×1.5** |
| ゴールド・EXP | **×5** |

**敵の出現数**

```
偏り = min(2, (ステージ-1) / 15)
敵数 = round( 乱数 × (3 + 偏り) + 1 + 偏り × 0.5 )   → 1〜5体に丸める
```

**メタルスライム**

| 項目 | 値 |
| --- | --- |
| 出現率 | **1%**（ボス戦を除く） |
| HP | **10** 固定 |
| 物理ダメージ | **1** 固定 |
| 魔法 | **無効** |
| 逃走 | **10秒** |
| EXP | 1戦闘ぶんの **×25** |
| ゴールド | **×3** |

## 5. 経済・報酬

| 項目 | 式 / 値 | 出典 |
| --- | --- | --- |
| ゴールド（1戦闘） | `8 × 倍率(3.0)` | `enemies.js`。装備の強化費用の基準でもあるので、総HPと同じ伸びにしてある |
| EXP（1戦闘） | `9 × 倍率(3.0)` | `enemies.js`。総HPと同じ伸びなので、レベルは最後まで意味を持ち続ける |
| 1ステージの戦闘数 | **10**（うち1がボス） | `enemies.js` |
| 「証」のドロップ | ステージ**25**以上のボスで **8%** | `enemies.js` |
| オフライン効率 | **50%** | `save.js` |
| オフライン上限 | **12時間** | `save.js` |
| オフライン計算の想定 | 1ステージ **150秒** | `save.js` |
| 装備の強化費用の基準額 | ⚠ 帯開始のギル **×2** | `inventory.js` の `baseCost` |

> **`baseCost` の係数は 5 → 2 に下げた。**
> ギルが指数（1.09/ステージ）だった頃は帯の中で収入が74倍に増えるので、
> 帯の後半でまとめて払えた。べき乗にすると帯の中の伸びが3倍程度しかなく、
> 合成がほとんど実行できなくなる（1周で合成6回・URはすべてガチャ直引き＝運次第）。
> 2 にすると合成が回るようになり、到達ステージのばらつきが大きく減った
> （6回中3回が停止 → 1回）。

## 6. 現在のバランス（実測）

編成：戦士 / モンク / 白魔道士 / 黒魔道士、オートON。
ヘッドレスsim（装備を最善手で付け替え・強化・合成し、ガチャは引けるだけ引き、
全滅したら遺物を受け取る）。1ステージに30分かかった時点を「壁」としている。

### 6.1 到達ステージ（8回）

## 7. 強化要素を足すときの注意

壁の位置を決めているのは、次の3つの比。

| 決めているもの | 定数 | 場所 |
| --- | --- | --- |
| ⚠⚠ 到達ステージ | 総HPの指数 **3.0** | `enemies.js` の `HP_EXP` |
| ⚠⚠ 全滅の回数 | 敵ATKの指数 **3.3**（総HPより速いぶんが全滅になる） | `enemies.js` の `ATK_EXP` |
| ⚠ 序盤の急さ | 原点のずらし **15** | `enemies.js` の `SHIFT` |
| ⚠ Lv75に届くステージ | EXPの指数 **3.0** ＋ 必要EXPの係数 **9** | `enemies.js` / `stats.js` |
| ⚠ 合成が回るか（＝ばらつき） | 強化費用の基準額 **帯開始のギル×2** | `inventory.js` の `baseCost` |
| ⚠ ステージ40前後を越えられるか | 実績「大陸踏破」**10ステージ刻み +30%** | `data/achievements.js` |
| 装備で伸ばせる総量 | レア度倍率（UR 5.0625）× レベル上限（+0.05×49） | `inventory.js` |
| 遺物を取る価値があるか | 遺物の効果量（1/5だと罠） | `data/relics.js` |

**必ず守ること**

1. **指数（`a^n`）を持ち込まない。** プレイヤー側の強化はレベル75・装備UR Lv50・
   遺物40個と、どれも上限がある。指数の相手にはいずれ必ず負けて詰む。
   新しい数値を足すときも `((n + 15) / 16)^p` の形にそろえること。
2. **敵ATKと総HPは別の指数。** 総HPは「1ステージの所要時間」を決め、
   その差ぶんが「全滅するかどうか」になる。遺物は全滅でしか手に入らないので、
   敵ATKを総HPと同じにすると遺物が丸ごと死ぬ。
   逆に上げすぎると、増えた全滅の回数ぶんそのまま到達ステージが落ちる。
3. **敵のDEF・AGIは線形のまま**にする。割合として効くので、指数にすると
   プレイヤーの数値をいくら上げても軽減され続けて詰む。
4. **ギルとEXPは総HPと同じ指数**にしておく。
   ギルをずらすと装備の強化費用が合わなくなり、EXPをずらすとレベルが
   途中で無意味になる（速すぎ）か一生届かない（遅すぎ）。
5. **帯倍率を入れてはいけない**（決定事項）。帯が変わるたびに装備が強くなると、
   装備の伸びが「一度きり」ではなく複利になる。
6. **実績は加算のみ。** 乗算（`form:'mul'`）の仕組みは残っているが、いまは
   誰も使っていない。1つでも乗算を入れると、そこだけが指数として復活する。

**強化要素を足したら測り直す**

```sh
node /path/to/sim2.mjs 250        # 壁の位置と各ステージの所要時間が出る
```

味方を硬く／強くする要素を足したときは、総HPの指数（`HP_EXP`）を上げて戻す。
べき乗にしてからは 0.1 動かして到達ステージが10前後ずれる程度で、
指数だった頃（0.01 で10ステージ以上）より格段に扱いやすくなっている。
それでも**必ず実測すること**。
