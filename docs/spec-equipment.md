# 装備システム 仕様（ドラフト）

実装前の設計文書。**[決定]** は指示済み、**[仮]** はこちらで置いた案、
**[要決定]** は判断が必要なもの。

> 入手方法の2つ目は途中で切れていましたが、通貨が「アレキサンドライト」と
> 指定されたので**ガチャ**として §6.2 に書いています。

---

## 1. 全体像

装備は **4部位 × レア度5段階 × レベル** で強さが決まる。

```
装備の性能 = 基礎値（ドロップしたステージに依存）
           × レア度倍率
           × レベル倍率
```

- **レベル**はギルで上げる。レア度ごとに上限がある
- 上限まで上げた**同じ名前の装備**を重ねると、1つ上のレア度になる（レベルは1に戻る）
- 入手は**ボスドロップ**と**ガチャ（モグボナンザ）**の2つ

**レア度は「アイテムの種類」ではなく「その1本の状態」** **[決定]**

同じ名前の装備が、レア度違いで共存する。

```
Nスファライ  ×2 ＋ ギル → Rスファライ
Rスファライ  ×3 ＋ ギル → SRスファライ
SRスファライ ×3 ＋ ギル → SSRスファライ
SSRスファライ×3 ＋ ギル → URスファライ
```

「スファライ」はモンクの格闘武器。名前がそのまま**育てる対象の識別子**になる。
最終的にはどの装備もURまで到達できる。

## 2. レア度 **[決定]**

| レア度 | レベル上限 |
| --- | --- |
| N | 10 |
| R | 20 |
| SR | 30 |
| SSR | 40 |
| UR | 50 |

**レア度倍率 — 1.5倍ずつ** **[決定]**

| レア度 | 倍率 | レベル倍率（上限時） | 上限まで育てた実効倍率 |
| --- | --- | --- | --- |
| N | 1.000 | 1.45（Lv10） | 1.45 |
| R | 1.500 | 1.95（Lv20） | 2.93 |
| SR | 2.250 | 2.45（Lv30） | 5.51 |
| SSR | 3.375 | 2.95（Lv40） | 9.96 |
| UR | 5.063 | 3.45（Lv50） | 17.47 |

**レベル倍率** **[仮]**：`1 + 0.05 × (Lv - 1)`

> **合成した直後は一時的に弱くなります。**
>
> 上限まで育てたSR（5.51）×3 を合成すると SSR Lv1（3.375）になるので、
> その1本だけを見ると **39%落ちる**。育て直せば 9.96 まで伸びて必ず超える。
>
> 「素材を上限まで育てる → 合成 → また育てる」というループ自体が設計意図なので
> これは受け入れてよいと考えているが、体感として気になる場合は
> **レベル倍率を `1 + 0.01 × (Lv-1)` まで下げる**と、
> どの段階でも「合成した瞬間に強くなる」状態を作れる（レア度の刻み1.5倍を下回るため）。
> ただしレベル強化の手応えは薄くなる。 **[要決定]**

## 3. 装備の区分（内部情報） **[決定]**

アイテムは内部的に2種類に分かれる。プレイヤーには明示しない。

| 区分 | 入手 | 位置づけ |
| --- | --- | --- |
| **ドロップ装備枠** | ボスドロップ | 基本の供給源。合成の素材になる |
| **ガチャ限定装備** | ガチャのみ | 同じレア度でも性能が高い、または固有の効果を持つ |

**ガチャ限定装備の優位性：性能 +30% ＋ 特殊効果** **[決定]**

同じレア度・同じレベルでも、ガチャ限定装備はドロップ品より強い。

| 差 | 内容 |
| --- | --- |
| ステータス | **+30%** |
| 特殊効果 | 1本につき1つ（ダブルアタック率+8%、ヘイト倍率+0.3 など） |

特殊効果の一覧は **[装備リスト](../data/equipment.csv)** の「特殊効果」列にある。

**ドロップ品だけでもURまで到達できる。**
合成が N→R→SR→SSR→UR とつながっているため。
ガチャの価値は「+30%」「特殊効果」「集める速さ」の3つになる。

## 4. 装備グループ **[決定]**

### 4.1 防具（鎧・脚）— 3グループ

| グループ | 対象ジョブ |
| --- | --- |
| **魔道士装備** | 白魔道士 / 黒魔道士 / 赤魔道士 |
| **重量装備**（タンク系） | 戦士 / ナイト / 暗黒騎士 |
| **軽量装備** | モンク / シーフ |

> いまは「重 = 戦士 / 中 = モンク・赤魔道士 / 軽 = 白・黒・シーフ」になっている。
> 指定に合わせると **赤魔道士は魔道士装備へ、モンクは軽量装備へ**移る。
> 中量というランクは無くなり、3グループに整理される。

**[要決定]** 未実装の上級ジョブの割り当て。
獣使い・吟遊詩人・狩人・侍・忍者・竜騎士・召喚士・青魔道士・コルセア・
からくり士・踊り子・学者・風水士・魔導剣士 の14ジョブ。
→ v2でジョブを追加するときに決めればよい（データ側は `armorGroup` を持たせるだけ）。

### 4.2 武器 — ジョブ専用 **[決定]**

武器はジョブごとの専用装備。他ジョブには装備できない。

| ジョブ | 武器 |
| --- | --- |
| 戦士 | 斧 |
| モンク | 格闘 |
| 白魔道士 | 棍 |
| 黒魔道士 | 杖 |
| 赤魔道士 | 片手剣 |
| シーフ | 短剣 |

> ジョブ専用にすると、**育てたいジョブを編成に入れてボスを回す**動機が生まれる。
> 一方で、ジョブを乗り換えるときは武器を一から集め直すことになる。

### 4.3 アクセサリ — 全ジョブ共通 **[決定]**

制限なし。どのジョブにも装備できる。

## 5. レベル強化と合成

### 5.1 レベル強化（ギル） **[決定：ギルで強化する／数値は仮]**

**費用は線形** **[決定]**

```
Lv n → n+1 の費用 = floor( 基礎費用 × レア度係数 × n )
```

**[仮]**

| 項目 | 値 |
| --- | --- |
| 基礎費用 | ドロップ元の帯のゴールド獲得量に比例させる |
| レア度係数 | N 1.0 / R 1.5 / SR 2.2 / SSR 3.2 / UR 4.6 |

上限まで育てる総額は `基礎費用 × レア度係数 × 上限×(上限+1)/2`。

| レア度 | 上限 | 総額（基礎費用 = 1 のとき） |
| --- | --- | --- |
| N | 10 | 55 |
| R | 20 | 315 |
| SR | 30 | 1,023 |
| SSR | 40 | 2,624 |
| UR | 50 | 5,865 |

> 線形にしたのは意図的。指数だと後半のレベルが実質到達不能になり、
> **ギルが装備強化だけに吸われて他の使い道がなくなる**。
> 線形なら「後半ほど楽になる」ので、余ったギルを他の用途に回せる。

**[要決定]** 1段階ずつ上げるか、まとめて上げられるか。
→ 上限50まで1回ずつタップさせるのは苦痛なので、
　**「最大まで上げる」ボタンを用意する**のが前提。

### 5.2 合成 **[決定：流れ／数値は仮]**

**上限レベルに達した装備どうし**を合成すると、1つ上のレア度になる。
合成後のレベルは **1に戻る**。

| 合成 | 必要数 | 状態 |
| --- | --- | --- |
| N → R | N × **2** ＋ ギル | **[決定]** |
| R → SR | R × **3** ＋ ギル | **[決定]** |
| SR → SSR | SR × **3** ＋ ギル | **[決定]** |
| SSR → UR | SSR × **3** ＋ ギル | **[決定]** |

この数だと **UR 1個 = SSR 3個 = SR 9個 = R 27個 = N 54個**。

**合成の材料は同じ名前の装備** **[決定]**

Nスファライを重ねられるのはNスファライだけ。別の格闘武器とは混ぜられない。

> これは前回の仮案（同じ部位・同じグループなら何でも可）を**否定する決定**。
> 特定の1本を集中的に狙うゲームになるので、
> **ガチャと ドロップの排出プールに何種類あるか**が難易度を直接決める（§6.3）。

**合成費用** **[仮]**：`素材1個を上限まで育てる総費用 × 0.5`

> **注意：合成のたびに育成コストが丸ごと消えます。**
> 「上限まで育ててから合成」「合成後はLv1」というルールなので、
> UR 1個を作るまでに **N54個ぶんの育成費用**を払うことになる。
> これは意図的な設計だと理解していますが、ギルの需要が非常に大きくなるので、
> ゴールドの獲得量（現在 `8 × 1.40^(n-1)`）は上方修正が必要になる見込みです。

## 6. 入手方法

### 6.1 ボスドロップ **[決定]**

**通常ボス**を倒したときにドロップ枠が判定される。

```
ドロップ率 = 20%（基本）
           + シーフのトレジャーハンター
           + アクセサリのドロップ率補正
```

**100%を超えたぶんは追加の抽選になる。**

```
確定数   = floor(ドロップ率 / 100)
追加抽選 = ドロップ率 の端数%で1個
```

例）150% → **100%で1個 ＋ 50%の抽選で1個 = 最大2個**

**トレジャーハンターの寄与は半分** **[決定]**

ゴールド用の数値（`10 + Lv×0.8`%）の**半分**をドロップ率に足す。
Lv75なら 1人あたり +35%。

| 編成 | ドロップ率 | 結果 |
| --- | --- | --- |
| シーフなし | 20% | 20%で1個 |
| シーフ1人（Lv75） | 55% | 55%で1個 |
| **シーフ4人（Lv75）** | **160%** | **1個確定 ＋ 60%で もう1個** |

> シーフ4人は装備集めに特化した編成として成立する。
> 一方でボス戦の火力・耐久が落ちるので、周回効率とのトレードオフになる
> （シーフは装備集めに強く、戦闘は弱いというジョブ像に沿う）。

**落ちるレア度 — N と R のみ** **[決定]**

| レア度 | 確率 |
| --- | --- |
| N | **98%** |
| R | **2%** |
| SR / SSR / UR | ドロップしない |

SR以上はガチャか、合成でしか手に入らない。

**落ちる部位** **[仮]**：武器 / 鎧 / 脚 / アクセサリ から各25%。

**落ちる装備は編成に関係なく、その帯の全対象から抽選** **[決定]**

編成していないジョブの武器も落ちる。
使う予定のない装備も素材として貯まるので、あとでジョブを乗り換えるときに効いてくる。

### 6.1.1 ドロップ装備は50ステージごとに入れ替わる **[決定]**

| 帯 | ステージ | 装備シリーズ |
| --- | --- | --- |
| 1 | 1〜50 | オニオン系（オニオンソード など） |
| 2 | 51〜100 | ブロンズ系 |
| 3 | 101〜150 | アイアン系 |

その帯にいる間は、その帯の装備しか落ちない。
帯をまたぐと**別名の装備**になるので、合成の素材としては引き継げない。

**ステータスは帯をまたいでも据え置き（帯倍率 = 1.0）** **[決定]**

---

### 6.1.2 帯倍率は設けない **[決定]**

帯が変わっても装備のステータスは据え置き（帯倍率 = 1.0）。
帯をまたいだ後は **ガチャ装備を使い続けるのが前提**になる。

- ドロップ装備は帯ごとに別名 → 合成の素材としても引き継げない
- **ガチャ限定装備は帯に属さない**ので、帯をまたいでも育て続けられる
- 帯の切り替わりで失う戦力は、**実績ボーナスで埋める**

> 帯ごとの戦力の落差をどう埋めるかは
> **[実績ボーナスの仕様](spec-achievements.md)** に切り出した。
> ステージ踏破実績（50刻み＝帯の切り替わりと一致）を乗算にして、
> ドロップ装備を育て直すあいだの落差を消す設計にしてある。

**ただし、敵のカーブは下げる必要があります。**

プレイヤー側の倍率をすべて足しても（ジョブレベル×17、装備×22.7、
実績×2.2、ステージ踏破の乗算×5,359）合計 **約×460万**。
敵は現在 1.45/ステージなので、150ステージで `10^23`。**17桁足りません。**

```
150ステージを踏破可能にする敵の伸び ≒ 1.11 / ステージ
```

詳しい内訳は [spec-achievements.md §3](spec-achievements.md) を参照。

### 6.3 排出プールの種類数が難易度を決める

同名でしか重ねられないので、**プールに何種類あるか**で必要な回数が何倍にもなる。

**ガチャの排出プールは 13種**（`data/equipment.csv` のガチャ行）

| 部位 | 種類数 |
| --- | --- |
| 武器 | 6（ジョブごと） |
| 鎧 | 3（グループごと） |
| 脚 | 3（グループごと） |
| アクセサリ | 1 |

ドロップと同じく**編成に関係なく全種から抽選**する（§6.1 の決定に合わせる）。

**[要決定]** ピックアップを設けるか。
特定の1種を高確率にする枠があると、「今日はスファライを狙う」という遊び方ができ、
種類数による希薄化も避けられる。

### 6.4 「2日で UR 1個」を成立させる数値 **[試算]**

指定の目標（UR 1個 ≒ 2日）から逆算する。

**UR 1個に必要な N の数**

```
1 UR = 3 SSR = 9 SR = 27 R = 54 N
```

**N 1個ぶんの価値に換算した、11連（50個）の期待値**

| 枠 | 内訳 | N換算 |
| --- | --- | --- |
| 通常10枠 | N 4.0 / R 4.0 / SR 1.5 / SSR 0.45 / UR 0.05 | 31.8 |
| 確定1枠 | SR 0.75 / SSR 0.225 / UR 0.025 | 9.9 |
| **合計** | | **41.7 N相当** |

**種類数で割る**

13種に散るので、狙いの1種に集まるのは 41.7 ÷ 13 ≒ **3.2 N相当 / 11連**。

```
54 N相当 ÷ 3.2 ≒ 16.8回の11連 = 約 840個
```

→ **アレキサンドライトを 1日 420個前後**配ると、目標の「2日で1個」に合う。

（実際には最初のURは「13種のうち最も早く揃ったもの」になるため、
　運の良い1種が先に到達する。体感はこの試算より少し早い）

**[要決定]** この配布量でよいか。調整の効くところは3つ。

| 手段 | 効果 |
| --- | --- |
| アレキサンドライトの配布量 | 直接。いちばん素直 |
| 排出プールの種類数 | 種類を減らすと必要数が比例して減る |
| ピックアップの導入 | 狙った1種に集中できるので実質的に種類数を減らすのと同じ |

### 6.5 ギルの必要量が桁違いになる **[要検討]**

UR 1個を作るまでに、**すべての素材を上限レベルまで育てる**必要がある。

| 段階 | 個数 | 各々の到達レベル |
| --- | --- | --- |
| N | **54個** | Lv10 |
| R | **27個** | Lv20 |
| SR | **9個** | Lv30 |
| SSR | **3個** | Lv40 |
| UR | 1個 | Lv50 |

合計 **93個ぶんの育成費用**が、UR 1本のために消える。
しかも合成のたびにLv1へ戻るので、払った育成費用は毎回捨てることになる。

> **ギルの獲得量は上方修正が必須です。**
> 現在は `8 × 1.40^(ステージ-1)` ／1戦闘。
> 装備の育成が入ると需要が2桁は変わるので、実装時に必ず測り直す。

## 7. 所持と装備 **[要決定]**

**[仮]** 入手した装備は**共有の倉庫**に入り、各ジョブの4スロットに割り当てる。

- 防具はグループ単位なので、同じグループのジョブ間で使い回せる
- 武器はジョブ専用なので実質そのジョブ専用
- 同じ装備を2人に同時装備はできない

**所持上限 200個 ＋ 自動売却** **[決定]**

- 所持上限は **200個**
- **指定したレア度以下を自動でギルに変換**する設定を持つ（既定：なし）
- 上限に達した状態で入手した場合は、自動売却の対象なら売却、対象外なら入手しない

放置ゲームなので、寝ている間に溜まったNを自動処理できないと
起動のたびに整理作業が発生する。

## 7.5 装備1本のデータ **[仮]**

「同じ名前を重ねる」ため、装備は**1本ずつ独立した所持品**として持つ。

```js
{
  id: "eq_00417",        // 所持品の通し番号
  name: "スファライ",     // 育てる対象の識別子。合成はこれが一致する必要がある
  slot: "weapon",
  rarity: "SR",          // N / R / SR / SSR / UR
  level: 12,             // レア度ごとの上限まで
  source: "gacha",       // drop / gacha（内部情報・表示しない）
  baseStage: 24,         // どのステージ帯の装備か（基礎値がここで決まる）
  equippedBy: "mnk"      // 装備中のジョブ。未装備なら null
}
```

- **`name` が同じもの同士だけ合成できる**
- `rarity` と `level` はその1本の状態。同名でもバラバラ
- `baseStage` は入手時に固定。あとから上がることはない
- `equippedBy` があるので、同じ装備の二重装備を防げる

## 8. 既存の実装との差分

いまの実装（`js/data/equipment.js`）との違い。

| 項目 | 現在 | この仕様 |
| --- | --- | --- |
| 性能の決まり方 | 到達ステージのティアで自動計算 | ドロップ元ステージ × レア度 × レベル |
| 入手 | 自動で最適装備を装備している扱い | ボスドロップ / ガチャ |
| レア度 | なし | N / R / SR / SSR / UR |
| レベル | なし | ギルで強化、レア度ごとに上限 |
| 防具グループ | 重 / 中 / 軽（3ランク） | 魔道士 / 重量 / 軽量（3グループ・**割り当てが変わる**） |
| 武器 | ジョブの武器種ごと | 同じ（ジョブ専用） |
| アクセサリ | 全ジョブ共通 | 同じ |
| アイテムの持ち方 | 都度生成（所持の概念なし） | 1本ずつ独立した所持品（§7.5） |
| ガチャ | なし | モグボナンザ |

**移行で必ず起きること**

現在、プレイヤー側で**指数的に伸びる唯一の軸が装備**（耐久側1.90 / 火力側2.06）。
これをドロップ制に変えると、**装備の更新が運任せになるぶん平均的な戦力が下がる**。

→ ドロップ品の基礎値を「**ドロップ元ステージのティア**」に紐づけるのが必須。
　そうしないと、ステージ30で拾った装備がステージ1の装備と同じ強さになり、
　進行が完全に止まる。

→ そのうえで、いまの壁（ステージ31前後）は必ず動く。
　実装後に耐久側の伸びを測り直す前提で進める。
